Night 01

What is artificial intelligence?

In which Tumar fails a very old test.

ATA “Your box answers questions. Does that make it clever? My neighbour's parrot answers questions too.”

ARU “That's exactly what scientists argued about, Ata. It depends on what you mean by ‘intelligent’.”

The idea

Artificial intelligence is the field that studies and builds machines that perceive their surroundings, reason about them, and act to achieve goals. Russell and Norvig, in the main textbook for this course, sort definitions of AI along two axes: should a machine think or act, and should it copy humans or follow an ideal of rationality?

Like a humanRationally
ThinkingCognitive modelling. Build programs whose reasoning steps match human psychology.Laws of thought. Reason with formal logic, from correct premises to correct conclusions.
ActingTuring test. Behave so that a person cannot tell the machine from a human.Rational agent. Act to achieve the best expected outcome. This is the view the course takes.

In 1950 Alan Turing proposed the imitation game, now called the Turing test. A judge chats in text with a hidden human and a hidden machine. If the judge can't reliably tell which is which, the machine passes. Turing's point was practical: instead of arguing about what "thinking" is, test the behaviour.

The rational agent view is the most useful one for engineers, because rationality can be defined mathematically. A rational agent picks the action that maximises its expected performance, given what it has perceived so far. Ten nights from now, almost every algorithm in this book will turn out to be one way of making that choice.

Narrow vs general AI

Every AI system in use today is narrow AI: excellent at one task (recognising faces, translating text, playing Go) and helpless outside it. Artificial general intelligence (AGI), a system that could learn any intellectual task a human can, remains a research goal and a subject of debate.

A short history, one milestone at a time

  • 1943McCulloch and Pitts describe a mathematical model of a neuron, the seed of neural networks.
  • 1950Turing publishes “Computing Machinery and Intelligence” and proposes the imitation game.
  • 1956The Dartmouth summer workshop (McCarthy, Minsky, Shannon, Rochester) gives the field its name.
  • 1958Rosenblatt's perceptron learns to classify simple patterns.
  • 1966Weizenbaum's ELIZA imitates a therapist with simple pattern-matching rules, and people still confide in it.
  • 1970sThe first “AI winter”: promises outrun results and funding shrinks.
  • 1980sExpert systems built from hand-written if-then rules spread through industry.
  • 1986Rumelhart, Hinton and Williams popularise backpropagation for training multi-layer networks.
  • 1997IBM's Deep Blue beats world chess champion Garry Kasparov in a match.
  • 2012AlexNet wins the ImageNet image-recognition contest by a wide margin and starts the deep-learning boom.
  • 2016DeepMind's AlphaGo defeats Lee Sedol at Go, a game long thought too large for computers.
  • 2017The Transformer architecture (“Attention Is All You Need”) appears; today's large language models are built on it.
  • 2022ChatGPT is released and brings language models to the general public.
Myth

“AI is one single technology, like a robot brain.”

Fact

AI is a toolbox: search, logic, probability, optimisation and learning. Different problems need different tools, and this book covers each one.

Did you know?

ELIZA's creator was alarmed that people formed emotional bonds with a program that understood nothing. This later became known as the ELIZA effect: our tendency to read understanding into machine output.

Night 02

Intelligent agents

In which Tumar is given a broom and one rule.

ATA “A good shepherd watches, then acts. Eyes, then hands.”

ARU “That's an agent! Sensors are the eyes, actuators are the hands. Tumar, you're cleaning the yurt tonight.”

The idea

An agent is anything that perceives its environment through sensors and acts on it through actuators. What it senses at one moment is a percept; everything it has sensed so far is its percept sequence. The agent function maps percept sequences to actions, and the agent program is the code that implements it.

To design an agent, first write down its task environment with PEAS. Here is one for an automated taxi driving through Astana in winter:

Safe, fast, legal, comfortable trip; low fuel useRoads, other cars, pedestrians, snow and ice, passengersSteering, accelerator, brake, signals, displayCameras, lidar, GPS, speedometer, wheel-slip sensors

Five agent designs, from simple to smart

  1. Simple reflex agent. Acts only on the current percept with condition–action rules (“if dirty, then suck”). Works only when the environment is fully observable.
  2. Model-based reflex agent. Keeps an internal state, a model of the parts of the world it can't currently see.
  3. Goal-based agent. Knows what it wants to achieve and plans action sequences that reach the goal. This is where search (nights 3–4) comes in.
  4. Utility-based agent. Many outcomes reach the goal; a utility function scores how good each one is, so the agent can trade speed against safety.
  5. Learning agent. A learning element improves the other parts from experience, guided by a critic's feedback. Night 10 covers this.

Night 03

Uninformed search

In which a lost lamb is looked for in every direction at once.

ATA “When a lamb wandered off, my father sent one boy to each nearby well first. Only when all the near wells were checked did they ride to the far ones.”

ARU “That's breadth-first search! You explored level by level.”

The idea: problems as graphs

A goal-based agent solves a problem by search: it imagines sequences of actions before taking any of them. To search, we first formulate the problem precisely:

PartMeaningLost-lamb example
State spaceAll possible situationsWhich well the rider is at
Initial stateWhere we startThe family's aul
ActionsMoves possible in a stateRide along a track to a neighbouring well
Transition modelResult of an actionYou arrive at that well
Goal testAre we done?The lamb is at this well
Action costPrice of each stepKilometres ridden

The algorithm grows a search tree from the initial state. The frontier holds nodes that have been generated but not yet expanded. The only thing that changes between algorithms is which frontier node to expand next. Uninformed (blind) strategies use no knowledge about where the goal is.

  • Breadth-first search (BFS) uses a FIFO queue and expands the shallowest node first. It finds the path with the fewest steps.
  • Depth-first search (DFS) uses a LIFO stack and always goes deeper first. It needs very little memory but can wander far away or loop forever.
  • Uniform-cost search (UCS) expands the node with the lowest path cost g(n). It finds the cheapest path even when steps cost different amounts. This is Dijkstra's algorithm, with a goal test.
  • Depth-limited search is DFS that stops at depth ℓ. Iterative deepening (IDS) runs it with ℓ = 0, 1, 2, … and gets BFS's guarantees with DFS's small memory.
function BFS(problem):
    frontier ← queue with node(problem.initial)
    reached  ← {problem.initial}
    while frontier not empty:
        node ← frontier.pop_front()
        if problem.is_goal(node.state): return path to node
        for child in expand(node):
            if child.state not in reached:
                reached.add(child.state); frontier.push_back(child)
    return failure

Comparing them

Algorithms are judged on four criteria. Completeness: does it always find a solution if one exists? Optimality: does it find the cheapest one? Plus time and space complexity. In the table, b is the branching factor (moves per state), d the depth of the shallowest goal, m the maximum depth, and C* the optimal cost, with every step costing at least ε.

AlgorithmComplete?Optimal?TimeSpace
BFSYes¹Yes²O(bd)O(bd)
Uniform-costYes¹ ³YesO(b1+⌊C*/ε⌋)O(b1+⌊C*/ε⌋)
DFSNoNoO(bm)O(b·m)
Depth-limitedNoNoO(bℓ)O(b·ℓ)

Why does memory matter so much? With b = 10 and d = 10, BFS may store about 1010 nodes. At around 1 KB each, that's on the order of 10 terabytes. IDS for the same problem stores about 100 nodes.

Did you know?

The word algorithm comes from the name of al-Khwarizmi, a 9th-century mathematician from Khwarazm in Central Asia whose books brought step-by-step arithmetic methods to the wider world.

Night 04

Heuristics and A*

In which the stars are used to point the way.

ATA “Your blind search checks every well. A real herder looks up at Temirqazyq, the Iron Stake (the Pole Star), and rides toward home.”

ARU “A rough guess of which way is closer. That's a heuristic.”

The idea

An informed search uses a heuristic function h(n): an estimate of the cheapest cost from node n to a goal. On a map, straight-line distance is a classic heuristic. On a grid where you can only move up, down, left and right, it's the Manhattan distance |x₁−x₂| + |y₁−y₂|.

  • Greedy best-first search expands the node with the smallest h(n). It's fast when the heuristic is good, but it ignores the cost already paid, so it is not optimal and can be led into dead ends.
  • A* search expands the node with the smallest
f(n) = g(n) + h(n)   // cost so far + estimated cost still to go

A* was published by Hart, Nilsson and Raphael in 1968. It is optimal when the heuristic is admissible: it never overestimates the true cost, so h(n) ≤ h*(n). For graph search, the stronger condition consistency also guarantees optimality: h(n) ≤ c(n, a, n′) + h(n′) for every step, a kind of triangle inequality. Every consistent heuristic is admissible.

Why does admissibility matter? If h never overestimates, then f(n) never overestimates the cost of the best solution through n. So when A* finally pops a goal off the frontier, no unexplored path can still be cheaper.

Among admissible heuristics, larger is better. If h₂(n) ≥ h₁(n) for every n, then h₂ dominates h₁ and A* with h₂ never expands more nodes. A common way to invent admissible heuristics is to relax the problem: solve an easier version with fewer rules. Manhattan distance is the exact cost on a grid with the walls removed.

A worked example

Suppose Aru stands at S and the yurt is at G. Edge costs are in kilometres; h is the straight-line estimate.

NodeEdgesh
SS→A 2, S→B 46
AA→G 75
BB→G 33
G—0

A* expands S and adds A with f = 2+5 = 7 and B with f = 4+3 = 7 (a tie). Suppose it expands A first: that adds G via A with f = 9+0 = 9. Next the frontier holds B (7) and G (9), so it expands B, which adds G via B with f = 7+0 = 7. Now G with f = 7 is the smallest, and A* returns S→B→G, cost 7, the optimal path. Greedy search would also pick B here (h = 3 < 5). With different numbers, though, greedy can commit to a path that only looks close.

Myth

“A smarter heuristic should guess high so the search hurries.”

Fact

Overestimating breaks A*'s guarantee and it may return a worse path. The best heuristic is as large as possible without ever exceeding the true cost.

Did you know?

Variants of A* are still used for pathfinding in video games and robot navigation, more than fifty years after it was published.

Night 05

Local search and optimisation

In which Tumar climbs the wrong hill in the fog.

ATA “In thick fog a herder wanted the highest hill, to see his flock. He always stepped uphill. He reached a top, but it was only a small mound. The real hill was beside him in the fog.”

ARU “Hill climbing, stuck on a local maximum. Poor herder.”

The idea

Sometimes the path doesn't matter, only the final state. Examples: placing 8 queens so that none attack each other, scheduling exams, or tuning a design. Local search keeps a single current state and moves to neighbouring states, guided by an objective function. It uses almost no memory and works in huge or continuous spaces.

  • Hill climbing always moves to the best neighbour and stops when no neighbour is better. It can get stuck on local maxima, plateaus and ridges.
  • Random-restart hill climbing runs hill climbing many times from random starts and keeps the best result. If each run succeeds with probability p, you need about 1/p restarts on average.
  • Simulated annealing picks a random neighbour. It always accepts a better one. It accepts a worse one with probability eΔE/T, where ΔE < 0 is how much worse it is and T is a “temperature” that falls over time. Early on it explores freely; later it settles. The idea comes from slowly cooling metal so that its atoms find a low-energy arrangement (Kirkpatrick et al., 1983).
  • Genetic algorithms keep a population of candidate states. The fittest are selected, combined by crossover, and changed slightly by mutation, imitating natural selection.

Night 06

Adversarial search: games

In which Ata plays to win, and so does Tumar.

ATA “In togyz kumalak I don't only ask what my move does. I ask what your best answer to it will be.”

ARU “That's minimax: you assume your opponent plays perfectly against you.”

The idea

In a two-player, turn-taking, zero-sum game with perfect information (tic-tac-toe, chess, Go, togyz kumalak), one player's gain is the other's loss. Call the players MAX and MIN. The minimax value of a position is the outcome when both play optimally:

MINIMAX(s) = UTILITY(s) if terminal · max over actions if MAX to move · min over actions if MIN to move

Minimax explores the game tree depth-first: O(bm) time and O(b·m) space. For chess, b ≈ 35 and a game often lasts about 50 moves per player, giving roughly 35100 positions to examine, far too many. Two tricks help:

  • Alpha–beta pruning. Track α, the best value MAX can already guarantee, and β, the best value MIN can guarantee. When a branch can't change the decision (α ≥ β), skip it. The result is exactly the same as minimax. With perfect move ordering, the work drops to about O(bm/2), which lets you search twice as deep in the same time.
  • Cutoff and evaluation functions. Stop at a fixed depth and score the position with a heuristic evaluation function, e.g. a weighted sum of material in chess.

For games with chance (backgammon) we add chance nodes and use expectiminimax, which averages over dice outcomes. Modern Go programs such as AlphaGo combine Monte Carlo tree search (estimating values by simulating many random games) with neural networks that evaluate positions.

Tic-tac-toe is small enough to solve completely: there are only 255,168 possible games. Go has roughly 2×10170 legal board positions, more than the number of atoms in the observable universe. That's why AlphaGo needed learning, not brute force.

Night 07

Constraint satisfaction

In which Aru colours a map of Central Asia.

ATA “Seating guests at a toi: the two quarrelling uncles may not sit together, the eldest sits at the place of honour, the young ones near the door…”

ARU “Variables, domains and constraints. Ata, you've been solving CSPs your whole life.”

The idea

A constraint satisfaction problem (CSP) has three parts. Variables X₁…Xₙ. A domain of allowed values for each variable. Constraints that say which combinations of values are allowed. A solution is a complete assignment that breaks no constraint. Sudoku, timetabling and map colouring are all CSPs.

Our example: colour the five Central Asian countries so that no two neighbours share a colour. The variables are KZ, UZ, KG, TJ, TM. Each domain is {Sky, Gold, Rose}. The constraints are one "≠" for each shared border.

Solving it

  • Backtracking search is depth-first: assign one variable at a time, and when a constraint is violated, undo the last choice and try the next value.
  • Variable ordering. MRV (minimum remaining values) picks the variable with the fewest legal values left (“fail first”). The degree heuristic breaks ties by picking the variable with the most constraints on unassigned variables.
  • Value ordering. LCV (least constraining value) tries the value that rules out the fewest options for neighbours.
  • Inference. Forward checking removes inconsistent values from neighbours' domains immediately after each assignment. Arc consistency (the AC-3 algorithm) goes further: for every arc X→Y, every value of X must have a compatible value in Y.

Night 08

Logic and knowledge

In which Tumar learns to be certain.

ATA “If the dogs bark, a stranger is near. The dogs are barking. What do you conclude, robot?”

TUMAR “Beep. A stranger is near.”

ARU “Modus ponens! He's doing logical inference.”

The idea

A knowledge-based agent keeps a knowledge base (KB) of sentences in a formal language. It TELLs the KB what it perceives and ASKs the KB what to do; an inference procedure derives new sentences from old ones. The classic example in the textbook is the Wumpus World, a cave where the agent infers “there is a pit next door” from feeling a breeze.

Propositional logic

Sentences are built from symbols (P, Q, …) that are either true or false, joined with five connectives: ¬ (not), ∧ (and), ∨ (or), ⇒ (implies), ⇔ (if and only if). A model assigns true or false to every symbol. The KB entails α (written KB ⊨ α) if α is true in every model where the KB is true.

The most surprising row: P ⇒ Q is true whenever P is false. “If it rains, the steppe is wet” is not broken on a dry, sunny day.

Inference rules

  • Modus ponens: from α ⇒ β and α, infer β.
  • And-elimination: from α ∧ β, infer α.
  • Resolution: from (α ∨ β) and (¬β ∨ γ), infer (α ∨ γ). Together with conversion to conjunctive normal form, resolution is a complete method for proving entailment in propositional logic.
  • Forward chaining starts from known facts and fires rules until the query appears (data-driven). Backward chaining starts from the query and works back to facts (goal-driven); Prolog works this way.

First-order logic

Propositional logic needs a separate symbol for every fact. First-order logic adds objects, relations and the quantifiers ∀ (for all) and ∃ (there exists). One sentence can then cover a whole flock:

∀x Sheep(x) ⇒ EatsGrass(x)   ∃x Sheep(x) ∧ Black(x)
Did you know?

Al-Farabi, the 10th-century philosopher traditionally said to have been born near Otrar in what is now southern Kazakhstan, wrote extensive commentaries on Aristotle's logic. He was known as the “Second Teacher”, the first being Aristotle himself.

Myth

“Logic-based AI is obsolete.”

Fact

Logic still powers hardware and software verification, planning systems, databases and rule engines. Neuro-symbolic research tries to combine logic with learning.

Night 09

Uncertainty and Bayes

In which the dogs bark, but maybe it's only the wind.

ATA “Yesterday your robot said a stranger was near. It was a fox. Dogs bark at foxes too, you know.”

ARU “Right. The real world is uncertain. Tumar needs probability, not just true and false.”

The idea

Real agents rarely know things for sure. Sensors are noisy, the world is partially observable, and rules have exceptions. Probability lets an agent express a degree of belief between 0 and 1 and update it rationally as evidence arrives.

  • Prior P(A): belief before seeing evidence.
  • Conditional probability P(A | B) = P(A ∧ B) / P(B): belief in A once we know B.
  • Independence: A and B are independent if P(A | B) = P(A).

Bayes' rule

P(Cause | Effect) = P(Effect | Cause) · P(Cause) / P(Effect)

Bayes' rule turns knowledge that's easy to collect (how often a disease causes a positive test) into what we actually want to know (how likely a disease is, given a positive test). Its most important lesson is that the prior matters.

Live demo

1,000 people take a medical test

Move the sliders. Each dot is one person. Gold dots have the disease and test positive (true positives). Rose dots are healthy but test positive (false positives). Outlined dots are sick but test negative.

P(disease | positive)
9.2%
0.90×0.010 / (0.90×0.010 + 0.09×0.990)
≈ 9 true + 89 false positives

With the default settings (1% of people sick, 90% sensitivity, 9% false positives), a positive result means only about a 9% chance of disease. There are so many healthy people that their few false alarms outnumber the real cases. Doctors call ignoring this the base-rate fallacy.

Bayesian networks

A Bayesian network is a directed acyclic graph. Each node is a random variable, an arrow means “directly influences”, and each node stores a conditional probability table given its parents. Because each variable depends only on its parents, the full joint distribution factorises compactly:

P(x₁, …, xₙ) = ∏ᵢ P(xᵢ | parents(Xᵢ))

Ata's version: Wolf → Dogs bark ← Fox, and Wolf → Sheep scatter. Hearing barking raises belief in both wolf and fox. If we then see the sheep calm, belief in the wolf drops, so the fox becomes the more likely explanation. This is called explaining away.

Naive Bayes is a simple classifier that assumes all features are independent given the class. Early e-mail spam filters used it: P(spam | words) ∝ P(spam) · ∏ P(wordᵢ | spam).

Machine learning and neural networks

The idea

Machine learning (ML) builds programs that improve at a task with experience. Instead of hand-writing rules, we provide data, and an algorithm finds a function that fits it. Tom Mitchell's definition: a program learns from experience E with respect to task T and performance measure P if its performance on T, measured by P, improves with E.

Supervised learning comes in two kinds. Classification predicts a category, like ripe or unripe. Regression predicts a number, like a melon's weight.

Classic algorithms

  • Linear regression fits y = w·x + b by minimising squared error.
  • Decision trees ask yes/no questions about features. Each split is chosen to give the highest information gain, the largest drop in entropy H = −Σ p·log₂p.
  • k-nearest neighbours labels a new point by majority vote of its k closest training points.
  • The perceptron, a single artificial neuron, outputs 1 if w·x + b > 0, otherwise 0. After each mistake it updates w ← w + η(y − ŷ)x, where η is the learning rate. If the classes can be separated by a straight line, it is guaranteed to find one eventually.

Add an unripe melon deep inside the ripe group and training will never reach 100%. The data is then no longer linearly separable. A single perceptron can't learn XOR for the same reason (Minsky & Papert, 1969); that limit is why we stack neurons into layers.

From one neuron to deep learning

A neural network stacks layers of neurons: an input layer, one or more hidden layers, and an output layer. Each neuron computes a weighted sum and passes it through a nonlinear activation function (sigmoid, tanh, or ReLU = max(0, x)). Training works like this:

  1. Forward pass: compute the prediction.
  2. Loss: measure how wrong it is (e.g. mean squared error, or cross-entropy).
  3. Backpropagation: use the chain rule to compute how much each weight contributed to the error.
  4. Gradient descent: nudge every weight a little in the direction that reduces the loss. Repeat for many epochs.

Deep learning means networks with many layers. Convolutional networks see images, recurrent networks and Transformers read sequences, and large language models are Transformers trained on enormous amounts of text to predict the next token.

Training well: overfitting and evaluation

A model that memorises its training data but fails on new data is overfitting. A model too simple to capture the pattern is underfitting. So we split data into a training set (to learn), a validation set (to tune settings) and a test set (touched once, for the final score). Cross-validation, regularisation and more data all fight overfitting.

Myth

“If the model is 99% accurate, it's a great model.”

Fact

If only 1% of melons are rotten, a model that always says “ripe” is 99% accurate and completely useless. Check precision, recall and the confusion matrix too.

Ethics, limits and the road ahead

ATA “Ten nights. Your Tumar can search, plan, reason, doubt and learn. But tell me: who answers when he makes a mistake?”

ARU “We do, Ata. The people who build and use him.”

Capability brings responsibility. These are the questions the field is working on now:

  • Bias and fairness. Models learn from historical data, including its prejudices. A hiring model trained on past decisions can repeat past discrimination.
  • Transparency. Deep networks are hard to explain. People affected by automated decisions deserve to understand them; this is the field of explainable AI.
  • Privacy. Training data often contains personal information that must be protected.
  • Safety and misuse. Deepfakes, misinformation and autonomous weapons raise serious concerns.
  • Work. Automation changes jobs. Some tasks disappear and new ones appear.
  • Accountability. Laws are catching up. The EU AI Act sorts AI systems by risk level and sets stricter obligations for high-risk uses.

A–Z

Glossary

A* search
Best-first search on f(n)=g(n)+h(n); optimal with an admissible (tree search) or consistent (graph search) heuristic.
Admissible heuristic
A heuristic that never overestimates the true cost to the goal.
Agent
Anything that perceives its environment through sensors and acts on it through actuators.
Alpha–beta pruning
Skipping game-tree branches that cannot affect the minimax decision.
Backpropagation
Using the chain rule to compute how each weight in a network contributes to the error.
Backtracking search
Depth-first assignment of CSP variables that undoes a choice when a constraint is violated.
Bayes' rule
P(A|B) = P(B|A)·P(A)/P(B); updates belief given evidence.
Bayesian network
Directed acyclic graph of random variables with conditional probability tables.
Branching factor (b)
Number of successors of a state.
Constraint satisfaction problem
Variables, domains and constraints; a solution is a consistent complete assignment.
Entailment (⊨)
α follows from the KB if α is true in every model where the KB is true.
Evaluation function
Heuristic estimate of a game position's value, used when the search is cut off.
Frontier
Generated nodes waiting to be expanded.
Forward checking
After an assignment, removing inconsistent values from the neighbours' domains.
Genetic algorithm
Population-based local search using selection, crossover and mutation.
Heuristic h(n)
An estimate of the cheapest cost from n to a goal.
Hill climbing
Local search that always moves to the best neighbouring state.
Minimax
Game-tree value assuming both players play optimally.
Modus ponens
From α⇒β and α, infer β.
MRV
Minimum remaining values: pick the CSP variable with the fewest legal values.
Overfitting
Fitting the training data so closely that performance on new data suffers.
PEAS
Performance, Environment, Actuators, Sensors: a task-environment description.
Perceptron
A single linear threshold neuron trained with w←w+η(y−ŷ)x.
Rational agent
An agent that chooses actions maximising its expected performance measure.
Simulated annealing
Local search that sometimes accepts worse moves, less often as the temperature falls.
Supervised learning
Learning a function from labelled input–output examples.
Turing test
A behavioural test: can a judge tell the machine from a human in conversation?
Uniform-cost search
Expands the frontier node with the lowest path cost g(n).
